# rules / skills 記述規約

`.claude/` 配下の rules / skills を作成・編集する際は、次の規約を遵守すること。
rules / skills は人間向けの文書である前に Claude への指示プロンプトであり、予測可能な構造と端的な文がそのまま遵守率に直結する。

この規約は、指示として読まれる文書のためのものである。
通読される記事のための規範（japanese-tech-writing、cognitive-rhythm-writing）とは基準が異なり、太字の扱いのように正反対になる項目もあるが、用途が違うので矛盾ではない。

## 適用対象

外部から取り込んだ skills は対象外とする。
上流とバイト単位で一致させることが更新の前提であり、規約に合わせて書き換えると差分が生まれて追従できなくなる。

- 外部由来の skills は編集せず、上流の内容のまま置く
- 外部由来かどうかは、リポジトリ外に配布元があるかで判断する
- 外部由来の skills に手を入れる必要が生じたら、書き換えずに別ファイルへ差分を書く

## 文体

- 見出しと本文は日本語で記述し、コマンド・パス・識別子は原文のまま記載する
- 文末は箇条書きでは「〜する」とする（確認観点の列挙に限り「〜か」も可）
- 地の文の文末は、説明では「〜する」、遵守を求める命令では「〜すること」とする
- 文中太字は使わない（重要な規約は独立した項目に切り出し、配置の順序で重みを表現する）
- 矢印による省略表現は使わず、自然な文で書く
- 「以下」で漠然と指さず、「次の規約」「次の手順」のように対象を明示して指す
- リンクは参照セクションにのみ置き、本文では文書名で言及する
- 同じ概念の用語は表記を統一する（例として「プッシュ」と「push」を混在させない）
- 理由説明は規約や手順の項目に混ぜず、セクション冒頭の地の文に置く

## 箇条書き

- 1 項目には 1 つの規約だけを書き、複数の規約を同居させない
- 1 項目は 1 文で書き、例や短い補足は括弧で文中に畳む
- 各項目は単独で引用しても意味が通る自己完結文にする
- 項目はネストさせない（分けたくなったら各項目を自己完結文にして平坦化するか、セクションを分ける）
- 1 文のみの項目は末尾に句点を付けない
- リンクや例示の列挙に限り、項目は体言止めでよい

## 重複の禁止

規約の実体は 1 箇所（rule または参照先の方針書）にのみ置き、他のファイルからは参照する。
複製は二重管理になり、いずれ食い違う。

## rules の構成

rules は制約の列挙であり、作業手順やトラブルシュートは書かない（手順は skills に書く）。
次の順で構成する。

1. フロントマター — `paths` で適用対象を限定し、無関係な作業のコンテキストに載せない
2. 見出し直後の地の文 — 適用対象と「次の規約を遵守すること」
3. 規約本体 — セクションごとの箇条書き（規約が 1〜2 文で収まるセクションは地の文でもよい）
4. 参照 — 規約の根拠や具体値を持つ文書へのリンク

rules のフロントマターに書けるのは `paths` だけである。
`description` は skills のキーであり、rules に書いても読み込まれない。

## skills の構成

skills は手順書であり、次の順で構成する（該当がないセクションは省略してよい）。

1. フロントマター — `name` と、起動条件を網羅した `description`
2. 概要 — 何を一気通貫で行うスキルか（1〜2 文）
3. 原則 — 守るべき判断基準と、その理由
4. 成果物 — 生成・編集するファイルと性質の一覧
5. 手順 — 番号付きの作業ステップ
6. 注意点 — ハマりどころと回避策
7. 参照 — 規約・方針書へのリンク

`description` は YAML の literal スタイル（`|-`）で複数行に分け、1 行目に用途、続く行に起動条件を書くこと。
folded スタイル（`>-`）は改行を半角スペースに置換し、日本語の文間に不要なスペースが入るため使わない。

同種の項目を列挙するときは、同じ構造（用法・動作・使いどころ等）をすべての項目で反復する。

## Lint

編集後は markdownlint を実行し、エラーがない状態にすること。
テーブルは全角文字を幅 2 として、全行で罫線の桁を揃えること。

```shell
# リポジトリ直下で実行する
npx markdownlint-cli2 ".claude/**/*.md"
```

`.markdownlint-cli2.yaml` の `globs` は `docs/**/*.md` だけを対象にしているため、`.claude` 配下は引数で明示的に渡すこと。
